Install

maxcode is a Python CLI. It calls a separate engine binary for each step. Install both.

Python CLI

uvx --from git+https://github.com/RavaniRoshan/maxcode maxcode --help

From a checkout, use uv sync and uv run maxcode.

Engine

git clone https://github.com/RavaniRoshan/maxcode-engine.git
cd maxcode-engine/maxcode-rs
cargo build --release -p maxcode-cli --bin maxcode-engine
install -m 755 target/release/maxcode-engine ~/.local/bin/maxcode-engine

The adapter tries MAXCODE_ENGINE_BIN, then maxcode-engine on PATH, then stock codex 0.165 or newer on PATH. Stock Codex is the faster install; build the fork only if you want the rebranded binary or a future patch.

Config

Create maxcode.toml in the project root. The key is read from the environment named by api_key_env; it is never written to disk.

[provider.pollinations]
base_url    = "https://text.pollinations.ai/openai"
api_key_env = "POLLINATIONS_KEY"

[provider.local]
base_url    = "http://127.0.0.1:11434/v1"
api_key_env = "OLLAMA_API_KEY"

[planner]
provider = "pollinations"
model    = "openai"

[worker]
provider = "local"
model    = "llama3.2:3b"

[checks]
test = "python -m pytest -q"

[limits]
max_retries_per_step  = 3
max_cost_usd_per_task = 2.00
max_diff_lines        = 400
max_steps             = 12

Any OpenAI-compatible Responses endpoint works; Codex 0.165 removed Chat Completions support. The example above is the configuration used for the live logs in spike/.

Commands

CommandAction
maxcode run TASKPlan, edit, verify, and checkpoint a task.
maxcode plan TASKPrint the plan and stop.
maxcode undoRestore the last checkpoint.
maxcode cost [RUN_ID]Show token and cost totals for a run.
maxcode benchRun the benchmark suite.
maxcode versionPrint the installed version.

Flags: run --yes, run --config PATH, run --max-cost USD, plan --config PATH, bench --verifier on|off, bench --suite PATH.

How a run works

  1. Plan. The planner splits the request into ordered steps.
  2. Work. The worker edits the repo for one step through the engine.
  3. Verify. Tests, build, and lint run in a separate process. A step passes only when every check exits zero.
  4. Checkpoint. Every step starts from a git ref under refs/maxcode/, so a failed attempt has somewhere to return to.
  5. Retry. A failing step is restored and retried up to max_retries_per_step.

Detected checks cover Python, Node, Rust, and Go projects. Add or override commands in maxcode.toml.

Checkpoints and undo

Before each step, maxcode records a git ref under refs/maxcode/. On a verifier failure it restores the step's starting tree before retrying. If every retry fails, the run stops and leaves the last good checkpoint in place.

maxcode undo

Undo restores the tree to that snapshot, including removing files that did not exist at the checkpoint. Commit or stash unrelated work before you run it.

Cost report

Every run writes JSONL events under .maxcode/runs/. Planner and worker responses record input and output tokens. maxcode cost sums them and prices them from the configured model rates.

If a provider omits usage, the report marks the run partial instead of inventing a number. A task can be capped with run --max-cost or max_cost_usd_per_task.

Benchmark method

The harness runs a fixed task suite twice: once with the verifier enabled and once with it disabled. Each run records changed-file line counts, check output, tokens, cost, and final state.

maxcode bench --verifier on
maxcode bench --verifier off
uv run python -m maxcode.bench.report .maxcode/bench

A pass rate is published only alongside its raw log. See the benchmark page for the current publication status.
