benchmark

No score without a log.

A pass rate is only useful if you can inspect the run that produced it. This page publishes a number only next to the raw log, the task suite, and the model settings.

method

Same tasks. Two configurations.

The runner executes every task twice: once with the verifier enabled and once with it disabled. The verifier configuration runs the repository's own test command after each step and refuses to close a step that fails. The disabled configuration records what the model produced without that gate.

input

Pinned repositories

Each task names a public repository and an exact commit. The runner clones the commit, not a moving branch.

measure

Pass rate and cost

A task passes only when its score command exits zero. Tokens and dollars are summed per completed task.

evidence

Raw logs

Changed-file line counts, check output, token usage, cost, and final state are written under .maxcode/bench/ for every run.

default suite

20 runs, four Python projects

The default suite contains four pinned Python projects, repeated five times each. The repeats measure consistency across model calls; they are not 20 different codebases.

reproduce

Run it yourself

maxcode bench --verifier on
maxcode bench --verifier off
uv run python -m maxcode.bench.report .maxcode/bench

The runner and the suite live in src/maxcode/bench. Add your own tasks by dropping JSON files into the suite directory.
